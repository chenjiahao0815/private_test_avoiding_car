# 避车仿真测试

WSL 目录 `/home/linux/vehicle_total/avoiding_car/测试脚本`，对应容器 `capella-ros-core-1` 的 `/capella/避车测试/`。
避车程序在容器 `/root/avoid_ws`（源码挂在 `/root/avoiding_car`）。
所有脚本都在 WSL 里执行，会自动把 `容器/` 同步进容器。

## 目录

| 路径 | 作用 |
| --- | --- |
| `用例/<形状>_<方向>.sh` | 每个用例一个入口，直接执行即可 |
| `全部用例.sh` | 依次跑全部（或按关键字筛选的）用例，结果追加到 `logs/汇总.md` |
| `运行用例.sh` | 被上面两个调用：分配日志序号、同步、执行、拷回日志 |
| `同步到容器.sh` | 把 `容器/` 拷到容器 `/capella/避车测试/` |
| `容器/一键避车测试.sh` | 容器内入口：停旧仿真、起 nav2_opt 和避车节点、跑模拟上位机 |
| `容器/上位机场景.py` | 模拟上位机：定位、发通道、行驶、来车、通过性、避车、车离开、恢复行驶 |
| `容器/场景用例.py` | 全部用例的几何（通道多边形、行驶中心线、触发点），`--list` / `--check` |
| `容器/测试场/` | 空旷测试场 world 和地图（`生成测试场.py` 生成），70 m × 50 m，四周一圈墙 |
| `容器/避车测试.rviz` | RViz 模板，每次运行按用例自动居中缩放 |
| `容器/地图对齐标定.py` | 原地图 corner_world 的 Gazebo→地图对齐标定，平时不用 |
| `logs/` | 每次运行一个序号文件夹，见下 |

## 运行

```bash
cd /home/linux/vehicle_total/avoiding_car/测试脚本
./用例/U形圆弯_下进上出.sh                     # 自搜索停靠点，跑完保留画面，Ctrl+C 清理
./用例/U形圆弯_下进上出.sh --external          # 上位机下发外部停靠点（车头沿通道切线）
./用例/U形圆弯_下进上出.sh --external-no-yaw   # 下发不带朝向的外部停靠点，由找点节点定车头
./用例/U形圆弯_下进上出.sh --no-hold           # 跑完直接退出
./全部用例.sh                                  # 全部用例 × 自搜索、外部停靠点
./全部用例.sh U形 T形 --modes=auto,external,external_no_yaw
```

单个用例约 2~3 分钟（含启动导航）。每次都会先停掉之前的仿真再从头启动。

## 用例

除 `原地图弧形_左到右` 用原来的 corner_world 外，其余都在测试场里，通道宽 3 m。
机器人沿行驶方向右侧车道开，来车在左侧车道迎面开来；外部停靠点在机器人身后 3.5 m、通道右边沿外 1.3 m。

| 形状 | 方向 | 说明 |

| L形圆弯 | 左进上出 / 上进左出 | 半径 6 m 圆角拐弯 |
| U形圆弯 | 下进上出 / 上进下出 | 半径 6 m 掉头弯，开口朝右 |
| U形直角 | 下进上出 / 上进下出 | 两个直角组成的掉头 |
| T形 | 左到右 / 右到左 | 沿横杠行驶，下方有 3 m 宽支路 |

## 上位机判定 PASS 的条件

1. 机器人生成在通道起点，定位与 Gazebo 真值一致。
2. 通道拟合成功（两条长边都有采样）。
3. 来车时通过性返回「不可通过」。
4. 自搜索：行为树找到停靠点（z=10）；外部点：机器人停到下发的点。
5. 停稳后车头与停靠处通道切线夹角 ≤ 35°（不区分顺逆）。
6. 车离开后避车动作成功结束，机器人恢复行驶到终点。

## 仿真环境改动（只在运行期间生效，脚本退出即恢复）

- 不启动 Cartographer（`ROBOT_LOCALIZER_MODE=3D`），由脚本发固定 map→odom：容器里的 map.pbstream 不是仿真地图。
- 速度话题沿用容器环境变量。这台容器是 `cmd_vel`（Gazebo 订阅这个）。未设置时脚本才写成 `cmd_vel`，不用另一台机器上的 `cmd_vel_nav`。
- 前进速度：`一键避车测试.sh` 设 `MAX_LINEAR_VEL=1.0`。launch 用它覆盖参数文件里的 `max_vel_x` 和平滑器上限；参数文件本身也改成 1.0。容器环境变量仍是 0.5，不改 compose。
- 测试场用例：`TB3_WORLD=/tmp/avoid_field/avoid_field.world`，`map:=/tmp/avoid_field/avoid_field.yaml`。
  测试场文件每次运行前从 `/capella/避车测试/测试场/` 复制到 `/tmp/avoid_field/`：
  nav2 改写参数时会把中文路径转义坏，map_server 读不到地图。
- nav2_opt 启动时会改写 `outdoor_cleaner_qp_2.yaml`，脚本启动前备份、节点起来后立刻还原；
  最早的原始备份在容器 `outdoor_cleaner_qp_2.yaml.bak_before_agent_20261109`。
- 找点节点运行时参数 `outside_min:=1.1 outside_max:=1.4`（不改参数文件）。

## 缺陷与修复

### 1. 外部停靠点停成垂直于通道（测试脚本问题，已修）

现象：外部停靠点模式下，机器人在停靠点横着停，车头垂直于通道。

原因：模拟上位机下发的外部点 yaw 是「通道切线 − 90°」。找点节点对通道外的外部点（z=30）按设计保留上位机给的朝向，
所以机器人照着垂直方向停了。上位机原来只核对「停的朝向 = 下发的朝向」，没核对和通道的关系，所以一直判 PASS。

修复：`上位机场景.py` 外部点 yaw 改为通道切线、顺行驶方向；停稳后增加「车头与通道切线夹角 ≤ 35°」判定，
`上位机.log` 里的 `yaw_vs_corridor_tangent_deg` 和 `heading`（顺/逆行驶方向）记录实际结果。

001~023 中外部点模式的运行是旧朝向（垂直），024 起是新朝向。

### 2. 外部点不带 yaw 时，通道外的点车头固定朝 yaw=0（find_free_space，已修）

现象：上位机下发不带朝向（单位四元数）的外部停靠点，找点日志写「外部停车点没有发 yaw，将使用避让方向自行计算」，
但点在通道外时代码直接沿用单位四元数，车头固定朝地图 +x。L 形、U 形的竖直段会和通道差 90°。

修复：`find_free_space/src/avoidance_search.cpp` `findExternalPoint`：通道外且不带 yaw 的点，
投到所选长边，车头取该处侧边切线（与自搜索点、通道内外部点同一套 `parkingYawAlongSide`）；
投影处是拐角没有切线时保持原样并打日志。带 yaw 的通道外点仍然保持上位机给的朝向不变。
`isDefaultOrientation` 提到 `geometry.cpp` 供两处共用。

验证：`025_L形直角_上进左出_外部点无朝向`，找点日志「没有 yaw，车头取侧边切线 90.0°」，停稳后与通道切线差 0.2°。

### 3. 直角内拐角处切线判定不准（测试脚本问题，已修）

`031`/`045`：U形直角的外部点落在内拐角，往内偏 2.8 m 已超过行驶线圆角半径 2.5 m，投影回不到原弧长，算出 42° 误判。
外部点改为直接比较下发处的行驶线切线，自搜索点在目标点投影附近 ±1.5 m 内投影。`046` 复测 PASS（11°）。

### 待确认：T 形路口，自搜索停靠点绕过路口拐角，车头垂直于主通道（`034`、`035`）

T形_左到右：机器人右侧是有支路的那条长边，道路模型把支路两侧墙也算在这条长边里。
找点从机器人垂足沿长边往后 3.0~3.3 m 找，垂足离路口拐角只有 2.2 m，搜索带绕过拐角落到支路右墙上，
候选点在支路墙外 1.25 m，车头取支路墙切线（90°），和主通道垂直，和你说的「大体沿切线」不符。
`035` 外部点在支路口里（通道内），行为树回退到同一个自搜索点。T形_右到左（右侧没有支路）正常。

### 待确认：自搜索带整段压在拐角上，找不到停靠点（`030`）

U形直角_下进上出：机器人在竖直连接段，往后 3.0~3.3 m 正好是内拐角。拐角前后约 0.5 m 的采样标记为拐角、没有唯一切线，
3 个站位全被跳过，「一共0个候选避让点」，行为树中止避车动作。触发点挪开 1 m 就不会碰到。

### 待确认：自搜索停靠点车头总是从通道 start 指向 end

`parkingYawAlongSide` 注释写明「停靠朝向：侧边从 start 到 end 的切线」，start 是 x 较小的那一端。
所以从右往左（或上进左出等）行驶时，停靠车头和行驶方向相反（`heading: 逆行驶方向`），恢复行驶要原地掉头。
朝向沿切线没问题，只是顺逆取决于通道端点而不是机器人行驶方向。这是现有设计，没有改，是否要改成顺行驶方向需要你确认。
