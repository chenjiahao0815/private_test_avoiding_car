## 场景

矩形通道 x 15~45、y 18.5~21.5（宽 3 m）。机器人从左往右沿右侧车道开（y=19.75），右手南边是近侧长边，左手北边是远侧长边。
来车在机器人前方 6.5 m 迎面开来，触发点默认在通道起点后 14 m。

禁扫区通过 `/cleaning_tool_retraction_areas`（`Polygons`，latched）发布，找点节点就是从这个话题读禁扫区的。
都是贴着长边外侧的带子，不盖通道本身：

| 名字 | 范围 | 用途 |
| --- | --- | --- |
| `near` | 南边外侧 x 13~47（伸出两头短边） | 堵住近侧 |
| `far` | 北边外侧 x 13~47 | 堵住远侧 |
| `near_close` | 南边外侧 x 25~44 | 只堵机器人身后 4.5 m 以内，原来 3~4 m 的范围没点 |

动态车 `/car_information_all`（10 Hz）：`none` 空，`busy` 一直有车，`flicker` 有车 2 秒、空 2 秒交替，`silent` 不发（模拟话题断流）。

| 用例 | 设置 | 期望 |
| --- | --- | --- |
| 矩形_近侧停靠 | 不堵 | 直接批准近侧（side 1），停右侧，不进远侧等待 |
| 矩形_远侧无车 | 堵 near | 远侧连续 3 秒无车、下一次找点确认后批准远侧（side 2），停左侧 |
| 矩形_远侧持续有车 | 堵 near，busy | 4 秒后放弃远侧走靠右；靠右跟踪开始 5 秒内不采纳远侧；看到靠右路径 1 秒后动态车清空 |
| 矩形_远侧车断续 | 堵 near，flicker | 4 秒和 3 秒都凑不满，等满 15 秒放弃走靠右，其他同上 |
| 矩形_近侧加大范围 | 堵 near_close | 2 倍范围（3~8 m）里找到近侧点，直接批准 side 1 |
| 矩形_近侧框越界裁剪 | 触发点 6 m | 加大的近侧框越过通道起点短边，找点日志出现「裁到」，照样找到近侧点 |
| 矩形_两侧都堵 | 堵 near + far | 一个点都没有，全程靠右走完，不停靠 |
| 矩形_两侧都堵后放开 | 堵 near + far，靠右 1 秒后撤 far | 靠右往回开，重新找到北边的点停下 |
| 矩形_确认前来车 | 堵 near，找到远侧点 2 秒后来车 1 秒 | 3 秒无车计时清零重来，从开始等待到批准 ≥5.7 秒 |
| 矩形_动态车话题断流 | 堵 near，silent | 数据不新鲜时 3 秒/4 秒计时暂停，只能等满 15 秒放弃走靠右 |
| 矩形_等待中近侧放开 | 堵 near，flicker，找到远侧点 1 秒后撤 near | 远侧还在等待，下一次找点拿到近侧点直接批准 side 1，停右侧 |
| 矩形_双侧关闭对照 | 堵 near，`GARAGE_ENABLE_DUAL_SIDE_AVOIDANCE=false`、`enable_dual_side:=false` | 退回老行为树 `garage_vehicle_avoidance.xml`，绝不找远侧，直接靠右 |

注意：靠右路径会让机器人掉头往通道起点开。掉头之后北边变成机器人的「近侧」，所以靠右之后找到的北边点 side 是 1，
这两个用例按停靠的实际位置（通道左侧/右侧）判定，不按 side。

## 上位机判定 PASS 的条件

1. 机器人生成在通道起点，定位与 Gazebo 真值一致；来车时通过性返回「不可通过」。
2. 停靠：机器人停到最新一次 `/marker_parking_point`，车头与通道切线夹角 ≤ 35°；
   没走靠右时车头必须顺着行驶方向（倒进停靠点，车走后直接继续，不掉头）；停在期望的一侧。
   期望不停靠的用例，避车动作必须成功结束且机器人没停到停靠点。
3. 行为树时间线（`避车行为树_garage_navigator/garage_navigator.log`，墙钟）：
   - 批准的 side、是否进入远侧等待、是否走靠右、放弃原因（4 秒有车 / 15 秒超时）和期望一致；
   - 批准 side 2 前必须有「远侧点确认通过」，且从开始等待到批准 ≥ 3 秒（确认前来车 ≥ 5.7 秒）；
   - 「靠右跟踪开始」到「远侧屏蔽结束」≥ 5 秒，期间不进入远侧等待。
4. 找点日志包含期望的文字（裁剪用例）；双侧关闭时行为树日志显示老 XML，找点从不返回 side 2。
5. 车离开后避车动作成功结束，机器人恢复行驶到终点。

## 测试中发现并修改的代码问题

都已改代码、重新编译、复测。

1. **停靠车头掉头**（find_free_space，原有逻辑）：`_compute_avoidance_yaw` 按「背对来车」取车头，机器人从左往右开、来车从右边来，
   停靠点 yaw 是 180°，机器人倒进去之前要原地掉头，车走后再掉回来。改成沿长边方向、取和机器人当前车头一致的那个方向：
   倒进停靠点，车走后直接接着开。自搜索点和通道内的外部点都用这个。上位机加了「没走靠右时车头必须顺行驶方向」判定。
2. **找位姿时间戳相减报错**（find_free_space，原有 bug）：`_get_fresh_robot_pose` 里 `Time - Time` 时钟类型不一致抛 `TypeError`，
   找点直接失败。改成按节点时钟类型 `Time.from_msg` 再相减。
3. **找点动作不能取消、会并发**（find_free_space）：rclpy humble 默认拒绝取消，执行也不绑回调组，两个 goal 能同时跑。
   行为树 halt 找点后旧 goal 还在跑。加了取消回调（接受）、执行加锁、候选循环和等服务时检查取消，通过性服务调用加超时。
4. **远侧点确认**（行为树）：原来 Parallel 里找点只跑一次，连续 3 秒无车后批准的是等待开始时那次找点的结果。
   改成 WaitForFarSide 每个 tick 判断、找点按 1 Hz 重复，只批准「连续 3 秒无车之后才发出」的那次找点结果（`confirm_far`）。
5. **5 秒远侧屏蔽起点**（行为树）：原来在 commit 时就开始算，算路要 1~2 秒，真正开始跟踪靠右时屏蔽只剩 3 秒多。
   改到 NavigateThroughPoses 里算完路、开始 FollowPath 时 `arm_tracking`，同一次靠右只记一次。
6. **近侧框越过前方短边**（find_free_space）：近侧范围加到 2 倍后，机器人离通道起点近时搜索框越过短边直接报错。
   改成逐步裁短沿边上限，最多裁回原来的 `search_radius_max`，日志「沿边上限从 x m 裁到 y m」。
